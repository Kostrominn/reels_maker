# interview_reels

Модуль собирает вертикальные рилсы из снятого разговора на две-три камеры с точными субтитрами. Им собраны две партии интервью-рилсов, 59 роликов, у каждого файла есть отчёт о проверке качества.

Главное отличие от автоматической нарезки в [`main.py`](../docs/MAIN_PIPELINE.md): монтаж не угадывается. Ролик описывается декларативно в `plans.json`: какая камера когда в кадре, где склейки, что написано в каждом субтитре и чья это реплика. Модуль собирает ролик по плану и проверяет готовый файл.

```bash
pip install -r requirements.interview.txt
python -m interview_reels demo /tmp/reels_demo   # синтетический проект: рендер и все проверки за ~20 с
python -m interview_reels --help
```

## Принципы

Выработаны на реальных интервью, модуль помогает их соблюдать:

- **Смысл важнее всего.** Субтитр — это цитата живого человека. Если модели распознавания слышат слово по-разному, оно не попадает в субтитр: звук остаётся, а подпись не пишется. Выкинуть слово-паразит можно, заменить слово нельзя.
- **Чья реплика — проверяется.** Разница громкости между камерами говорящих не разделяет, по раскадровке ртов (`mouths`) их различить можно. Если и так непонятно, реплика звучит без субтитра. В быстром диалоге выручает разделённый экран (`split`): видно обоих, и приписывать реплику одной камере не нужно.
- **Фразы не обрубать.** Склейки ставятся в паузах, а не посреди мысли. Режется только мат, уход в сторону, длинные неразборчивые куски и имена посторонних людей.
- **Границы слов по звуку, а не по расшифровке.** Whisper растягивает последнее слово на паузу после него и ошибается на сотни миллисекунд. Поэтому `check-cuts` меряет уровень звука в точке склейки.
- **Наклейки и карточки** показывают только то, что прозвучало в ролике (числа, названия), и появляются точно на слове.

## Проект

Проект — это одна папка:

| файл | что в нём |
|---|---|
| `plans.json` | планы роликов (обязательно) |
| `rows.json` | карточки публикаций: заголовок, подпись, обложка |
| `pack.json` | тексты пака (`title`, `intro`, `order`, `label`, `heading`, `captions_title`, `qc_title`), папка `out`, `font`, `accent` |
| `qc_notes.json` | ручные пометки к отчёту: `{"06": {"remeasured": "…", "still_ok": "…", "visual": "…"}}` |
| `insets/` | картинки и наклейки, на которые ссылаются планы |

Пути к медиа в планах — абсолютные или относительные папки проекта. Готовые ролики кладутся в `out/`, промежуточные файлы — в `.cache/`; обе папки можно переназначить (`--out`, `--cache`).

## План ролика

Все времена в плане заданы во **времени расшифровки**, то есть в шкале опорной звуковой дорожки, с которой снимались субтитры.

```json
{
  "id": "05",
  "name": "05_Пример",
  "kicker": "ПРИМЕР",
  "title": ["Как устроен", "план ролика"],
  "accent": ["склейка", "камера"],
  "sources": {
    "g": {"video": "take1_guest.mov", "audio": "take1_host.mov", "advance": -1.483,
          "crop": "860:1528:60:250", "crop_alt": "800:1422:90:290"},
    "s": {"video": "take1_split.mov", "audio": "take1_host.mov", "advance": 2.0}
  },
  "clips": [["g", 3.2, 14.9], ["s", 14.9, 21.0]],
  "cues": [["g", 3.4, 5.1, "Реплика гостя"],
           ["s", 15.0, 16.2, "А здесь говорят оба —\nкамера показывает двоих"]],
  "insets": [[15.0, 17.0, "insets/st_example.png", 60, 260]],
  "clip_gains": [0.0, 1.5]
}
```

- **`sources`** — камеры. `advance` = время расшифровки − время в файле этой камеры для того же момента. Звук каждого клипа берётся из `audio`, файла в шкале расшифровки. Поэтому камеру можно переключить где угодно, даже посреди чужой реплики, чтобы показать реакцию.
- `crop` / `crop_alt` — кадрирование широкого кадра. Два подряд идущих клипа одной камеры получают чуть разную рамку, чтобы внутренняя склейка не читалась как брак. Без `crop` второй клип слегка приближается (`zoom_x`).
- **`clips`** — `[камера, начало, конец]`. Соседние клипы с одним `audio`, где конец одного равен началу другого, дают бесшовный стык: звук идёт непрерывно, режется только картинка.
- **`cues`** — `[камера, начало, конец, текст]`. Субтитр привязан к камере и показывается, только пока она в кадре. `\n` — перенос строки. Слова из `accent` красятся целиком: «плюсник» покрасит «плюсника», а «пи» не загорится внутри «олимпиаду».
- **`insets`** — `[начало, конец, картинка, x, y]`, не привязаны к камере: наклейки, чертежи.
- Звук: `clip_gains` (дБ на клип, можно поставить командой `balance`), `compress_audio`, `limit_audio` (потолок лимитера: для записей на один микрофон на улице, которые иначе не дотягиваются до −16 LUFS).

Карточка в `rows.json`: `id`, `title`, `caption`, `cover_source`, `cover_time` (время в файле камеры), `cover_kicker`, `cover_title` (строки), а также `note` и `audience` по желанию.

## Как собирается ролик

1. **Фрагменты.** `fetch SRC START DUR OUT [--hlg]` вырезает кусок из длинной записи, локальной, по URL или с Яндекс.Диска (`disk:/…`), не скачивая её целиком. Для камер iPhone в HLG нужен ffmpeg с фильтром `zscale` (`--ffmpeg` или `REELS_FFMPEG_HLG`).
2. **Синхрон.** `sync-audio REF CAM` сравнивает огибающие звука; на реальной записи два независимых окна совпали до 10 мс. Для камеры без звука `sync-motion` сравнивает движение в кадре: например, весь кадр гостя с областью его рук в кадре ведущего. Время создания файлов на iPhone округлено до секунды, записи могут сбиться посреди сессии, поэтому каждый фрагмент меряется отдельно.
3. **Расшифровка.** `words` (whisper small) даёт пословные тайминги, по ним выбираются склейки (`show-words`). У длинных файлов удобно расшифровать целое, а куски вырезать через `slice-words`.
4. **Кто говорит.** `mouths OUT.png 0.25 A-B файл:сдвиг:crop …` строит полосы кадров ртов с обеих камер.
5. **План** пишется в `plans.json`, затем идут `check-text` (всё влезает) и `check-cuts` (склейки в паузах). При необходимости `autofix` (раздвигает склейки в паузы и переносит длинные субтитры; перекрывающиеся клипы он не видит, поэтому план после него нужно просмотреть) и `balance`.
6. **Рендер:** `render ID`.
7. **Проверки готового файла:** `check-outputs` (контейнер, 1080 × 1920, 30 к/с, −16 LUFS, пик, чёрные кадры, фризы), `verify-sync` (липсинк, норма — меньше кадра), `verify-captions` (каждый субтитр найден на реальном кадре), `check-levels` (скачки громкости между клипами), `verify-text` (whisper medium читает готовый звук и печатает рядом с каждым субтитром). Спорные места переслушиваются узко: `spots-from-srt` → `hear` (окна по субтитру ±0,3 с и с контекстом, при необходимости с замедлением 0,85).
8. **Отчёт и пак:** `qc` пишет `QC_REPORT.md`, `package` делает обложки, `ПОДПИСИ.md`, `НАЧАТЬ_ЗДЕСЬ.md` и `СМОТРЕТЬ.html` с кнопкой «Скопировать подпись». `serve` поднимает локальный сервер с перемоткой видео.

`all` прогоняет шаги 5–8 подряд.

## Разделённый экран и наклейки

`split OUT.mov --top ФАЙЛ:СДВИГ:X:Y --bottom ФАЙЛ:СДВИГ:X:Y [--start 2.0]` ставит две камеры 1080 × 1920 друг над другом (без звука). Сверху зум 4/3, лицо на 45 % половины. Снизу зум 3/2, лицо на 70 %, чтобы плашка субтитров легла на стену над головой. В плане у такого источника `advance` равен `--start`, а звук берётся с опорной записи. `verify-sync` для него проверяет, что звук взят с нужного места: своей дорожки у него нет.

`sticker OUT.png emoji:❤️ text:120 accent:180` рисует наклейку в стиле пака. Ставится через `insets`, на 1–4 с.

## Шрифт и окружение

- Python 3.10+, ffmpeg и ffprobe в `PATH` (или `REELS_FFMPEG` / `REELS_FFPROBE`), `numpy`, `scipy`, `Pillow`. Для расшифровки — `openai-whisper`.
- Задуманный шрифт — [Manrope](https://fonts.google.com/specimen/Manrope) (SIL OFL 1.1, вариативный). В репозиторий он не входит. Положите `Manrope.ttf` в папку проекта или укажите `REELS_FONT` / `"font"` в `pack.json`. Без него берётся системный шрифт с кириллицей.
- Эмодзи для наклеек: Apple Color Emoji на macOS или Noto Color Emoji (`REELS_EMOJI_FONT`).

## Проверка

`python -m pytest tests/test_interview_reels.py` проверяет перевод плана в шкалу ролика, акценты, переносы, замер синхрона и склеек на синтетическом звуке и сквозной прогон демо-проекта. На реальных проектах модуль пересобирает ролики побайтно так же, как исходные скрипты, которыми они были сделаны.
